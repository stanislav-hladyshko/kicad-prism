# KiCAD Prism v5.1.0-alpha

This release makes Prism scriptable and opens it to AI assistants. It adds a
typed HTTP API, personal access tokens, a Python SDK and `prism` CLI, outbound
webhooks, and an MCP server that lets an assistant such as Claude Code read
designs, leave comments and start jobs with the signed-in user's permissions.
An optional set of admin-only diagnostics lets an assistant look into a
deployed server's health without shell access.

Everything new is off or unused until you turn it on. An installation that
changes nothing in `.env` behaves as before.

**Back up before upgrading.** Follow the [upgrade runbook](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.1.0-alpha/docs/UPGRADES.md).

- **Schema:** migrations 131–142 run at startup. They only add tables and
  columns.
- **PostgreSQL restarts once.** The release Compose file now starts PostgreSQL
  with `shared_preload_libraries=pg_stat_statements`, so `docker compose up -d`
  recreates the database container with the same data volume. A managed
  PostgreSQL needs nothing; the slow-query diagnostic then reports itself
  unavailable.
- **No design bundles are rebuilt.** `prism-kicad` stays at 0.14.0.

## Scripting

- Every API route is available under `/api/v1` with a typed response and a
  stable `operationId`; the OpenAPI document is at `/api/v1/openapi.json`. The
  unversioned `/api` paths keep working until v6.
- **Personal access tokens** (Settings → Personal access tokens) with scopes
  `api:read`, `comments:write`, `design:write`, `catalog:write` and `api:write`.
  A token acts with its owner's current role and expires within
  `PRISM_PAT_MAX_DAYS` (default 365).
- **Safe retries:** a write sent with an `Idempotency-Key` header returns the
  first response when repeated within 24 hours.
- **Events:** `GET /api/v1/events` and the live socket `/api/v1/events/live`
  report syncs, bundle builds, jobs, comparisons, comment changes and releases,
  kept for `PRISM_EVENT_RETENTION_DAYS` (default 30).
- **Python SDK and CLI** in `sdk/python` (`pip install ./sdk/python`): BOM
  export, comments, sync, release builds and comparisons, with `--wait` to follow
  a job.
- **Webhooks** (Settings → Webhooks) deliver events in order with signed
  bodies, retry with backoff, and stop on an endpoint that keeps failing.
  Targets on private networks need `PRISM_WEBHOOK_ALLOW_PRIVATE=true`.
- **Links to a view:** a viewer URL can name the revision, sheet, layer and the
  selected or highlighted components and nets, so a script or comment can open
  exactly what it means.
- CI templates in `examples/ci` review every pull request against Prism.

## AI assistants (MCP)

- Set `PRISM_MCP_ENABLED=true` and `PUBLIC_BASE_URL` to serve MCP at `/mcp`.
  Clients that support MCP OAuth connect with no token. For Claude Code, run
  `claude mcp add --transport http prism https://prism.example.com/mcp`.
- **Read tools:** projects and revisions, design search, components and nets,
  the BOM, comparisons, jobs, comments, the component catalog, Release Studio
  status, and `render_view` for a PNG of a schematic sheet, the PCB or 3D.
- **Write tools:** comments and replies, project sync, Release Studio builds,
  catalog drafts and import edits. An assistant starts read-only and asks for
  each write scope the first time it needs it.
- **Sign-offs stay with people.** Approving or publishing a release, catalog
  QA, admin changes and resolving comments are never tools; the assistant hands
  you a link instead.
- Comments an assistant writes carry an **Agent** badge naming the client.
- Admins choose which projects and tools MCP can reach under Settings → MCP,
  and every MCP call is audited (`PRISM_MCP_AUDIT_RETENTION_DAYS`, default 365).
- Designs an assistant reads are sent to that assistant's model provider.
  Limit MCP to the projects that may leave Prism this way.

## Ops diagnostics

- `PRISM_MCP_OPS_ENABLED=true` adds 13 admin-only tools with the `ops:read`
  and `ops:act` scopes:
  - job timelines and bundle build profiles;
  - route latency and request tracing;
  - slow queries;
  - pool, worker, cache and webhook health;
  - CPU profiles.
- Four fixed actions: cancel, requeue a failed or stuck job, rebuild one
  design bundle, and debug logging for at most 30 minutes.
- No SQL, shell or configuration tools. Output carries ids, timings and counts,
  with secrets, tracebacks and server paths removed.
- Each response carries an `X-Request-Id` header. Slow, failed and write
  requests are kept for 3 days, and route statistics for 7.

## Other fixes

- A zone-refill cache hit no longer records a KiCad refill run in the bundle's
  details.
- A board saved by a 2024 KiCad nightly with `(placement (expr …))` rule areas
  now fails with an error that says what to change.

## Known issues

- The SDK is not on PyPI yet; install it from the release's source tree.
- Where a sheet repeats a sheet-pin name, the `_N` numbers can be assigned in a
  different order from KiCad's. The nets themselves match.
- A board file with a missing parenthesis that KiCad tolerates, such as
  `(curved_edges no)filter_ratio 0.9)`, fails to parse.
- Simulation Studio is experimental.
